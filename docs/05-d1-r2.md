# 05 — D1 Database & R2 Storage

## Product Context

D1 is the single source of truth for all Wasabi workspace data. Every page, record, user, automation rule, knowledge base entry, and relationship lives in a single Cloudflare D1 (SQLite) database. R2 provides object storage for file attachments and document content. The worker (`worker.js`, ~9533 lines) exposes 150+ API endpoints that mediate all access to D1 and R2.

**Important:** Notion-linked databases are proxied through the worker to the Notion API in real time. They are NOT stored in D1 unless the user explicitly configures bidirectional sync via `sync_configs`.

## R2 Storage

**Bucket name:** `wasabi-docs`
**Binding:** `DOCS`

### Key Structure

```
docs/{doc_id}.json          — Document content (block arrays)
files/{file_id}_{filename}  — User-uploaded files
backups/{page_id}_{ts}.json — Sync backups
```

Files are referenced by the `r2_key` column in `documents` and `files` tables. The worker serves file content via signed URLs or direct proxy.
