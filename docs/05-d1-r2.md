# 05 — D1 Database & R2 Storage

## Overview

The Wasabi backend uses **Cloudflare D1** (SQLite) for structured data storage and **Cloudflare R2** for file/document persistence. All operations are performed through the Cloudflare Worker API (`worker.js`), accessed via the frontend through `src/lib/api.js`.

This document details every endpoint, parameter, response format, and table schema in the current codebase.

---

## D1 Tables & Schema

### Schema Overview

The D1 database contains the following tables, all defined in `worker.js` (lines 16-319):

#### Core Infrastructure

**connections** — Global key-value store for API credentials
```sql
CREATE TABLE IF NOT EXISTS connections (
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL,
  metadata TEXT DEFAULT '{}',
  updated_at TEXT DEFAULT (datetime('now'))
);
```
Stores: `notion`, `claude`, `monday`, Google OAuth tokens, etc.

**page_configs** — Page hierarchy and metadata
```sql
CREATE TABLE IF NOT EXISTS page_configs (
  id TEXT PRIMARY KEY,
  parent_id TEXT,
  title TEXT NOT NULL,
  icon TEXT DEFAULT '',
  page_type TEXT NOT NULL,
  sort_order INTEGER DEFAULT 0,
  config TEXT DEFAULT '{}',
  created_at TEXT DEFAULT (datetime('now')),
  updated_at TEXT DEFAULT (datetime('now'))
);
```
**Fields:**
- `page_type`: "workspace" | "folder" | "database" | "document" | "sheet" | "linked_notion" | "linked_monday"
- `config`: JSON with view definitions, settings, database IDs
- `sort_order`: Display order within parent folder

#### Table Storage

**table_schemas** — Column definitions for D1 tables
```sql
CREATE TABLE IF NOT EXISTS table_schemas (
  id TEXT PRIMARY KEY,
  columns TEXT NOT NULL,
  created_at TEXT DEFAULT (datetime('now')),
  updated_at TEXT DEFAULT (datetime('now'))
);
```
**columns field format:**
```javascript
[
  { name: "Task", type: "title", hidden: false },
  { name: "Status", type: "status", options: ["To Do", "Done"], color: "blue" },
  { name: "Due Date", type: "date" },
  // ... more columns
]
```

**table_rows** — Data rows for tables
```sql
CREATE TABLE IF NOT EXISTS table_rows (
  id TEXT PRIMARY KEY,
  table_id TEXT NOT NULL,
  cells TEXT NOT NULL,
  cell_versions TEXT DEFAULT '{}',
  sort_order INTEGER DEFAULT 0,
  archived INTEGER DEFAULT 0,
  metadata TEXT DEFAULT '{}',
  sync_dirty INTEGER DEFAULT 0,
  sync_retry_count INTEGER DEFAULT 0,
  created_at TEXT DEFAULT (datetime('now')),
  updated_at TEXT DEFAULT (datetime('now')),
  updated_by TEXT DEFAULT NULL
);
```
**Important Fields:**
- `cells`: JSON object mapping column names to values
- `cell_versions`: `{ "columnName": { version: 2, history: [...] } }` — tracks cell edit history for conflict detection
- `sync_dirty`: Flag (0|1) indicating row needs Notion sync
- `sync_retry_count`: Number of failed sync attempts
- `updated_by`: User ID or device ID of last editor (for multi-user attribution)

## API Endpoints

### Health & Initialization

#### GET `/health`
Worker health check.

**Response:**
```json
{ "ok": true, "timestamp": "2026-03-20T..." }
```

#### POST `/init`
Initialize D1 database (create all tables). Called once on first-time setup.

**Request:**
```json
{}
```

**Response:**
```json
{ "ok": true, "message": "Database initialized" }
```

#### POST `/factory-reset`
Drop and recreate all tables (admin only, destructive).

**Response:**
```json
{ "ok": true, "message": "Factory reset complete" }
```

## Conflict Detection & Merging

When updating rows with `merge_cells: false`, conflicts can be detected:

**Request:**
```json
{
  "cells": { "Task": "Updated task name" },
  "merge_cells": false
}
```

**Conflict Response:**
```json
{
  "accepted": { "Task": "Updated task name" },
  "conflicts": {
    "Status": {
      "local": "In Progress",
      "remote": "Done",
      "local_version": 3,
      "remote_version": 4,
      "local_updated_at": "2026-03-20T10:00:00Z",
      "remote_updated_at": "2026-03-20T10:05:00Z"
    }
  }
}
```

Resolution can be re-submitted with conflict instructions (CRDT-style last-write-wins or custom merge logic).

## Known Issues & Gaps

See `/sessions/focused-stoic-noether/code-review.md` for comprehensive security and logic issues. Key D1/API issues:

1. **Missing target_user_id in notifications** — Notifications are global, not per-user. All users see all notifications.
2. **No input validation on query filters** — SQL injection possible if filter values not escaped (though parameterized queries provide some protection).
3. **Missing audit logging on D1 mutations** — No logging of who changed what row when.
4. **Incomplete cell_versions tracking** — History entries not fully utilized for conflict resolution UI.
5. **Sync direction enforcement weak** — No validation that sync config direction matches actual Notion API calls.
6. **No rate limiting on file uploads** — Can upload unlimited files and exhaust R2 quota.
7. **R2 keys leaked in responses** — Exposing R2 key structure could enable directory traversal (low risk but poor practice).

## Performance Considerations

- **D1 Indexes:** `idx_rows_table`, `idx_sync_dirty`, `idx_task_activity_lookup`, etc. created for common queries. See worker.js lines 321-341.
- **Large batch queries:** Limit queries to <1000 rows per request to avoid timeout. Use pagination with offset/limit.
- **Cell versions bloom:** If tracking many edits per cell, cell_versions column can grow large. Consider periodic cleanup.
- **R2 object limits:** Cloudflare R2 supports objects up to 5 TB. Documents are stored as JSON, so typical Notion pages (50-500 KB) are fine.
